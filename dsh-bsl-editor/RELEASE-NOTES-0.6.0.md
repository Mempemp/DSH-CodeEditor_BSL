# dsh-bsl-editor v0.6.0

## Изменения

- **Принять или отклонить изменения прямо в файле.** У каждого блока изменений сразу под ним
  справа появились кнопки **Отклонить** и **Принять** — как в Cursor, но с поправкой на то, что
  дифф у плагина считается не против состояния «до правки модели», а против `HEAD`:

  - **Принять** — блок считается просмотренным. Подсветка и красный блок удалённых строк убираются
    вместе с ним, счётчик и переход по `Alt+↑` / `Alt+↓` начинают считать только непросмотренное.
    Файл при этом не меняется: правка уже лежит в нём, и коммитить для этого не нужно — это и была
    исходная жалоба, что «груз диффов для головы копится».
  - **Отклонить** — к `HEAD` возвращается ровно этот блок, а не весь файл: из diff'а вырезается
    патч одного куска и применяется `git apply -R`. Для правок, попавших в индекс (`git add`),
    используется `git apply -R --index` — откат идёт и по индексу, и по файлу, иначе изменение
    осталось бы висеть в индексе и подсветка вернулась бы на следующем же обновлении.
  - Перед откатом хост заново берёт diff и сверяет строку `@@` присланного куска: если по этому
    номеру лежит уже другой кусок (агент успел поправить файл, пока рисовался вид) — отказ с
    сообщением «файл изменился», а не откат вслепую. При несохранённых правках в буфере откат
    не выполняется вовсе: он стирает правки в рабочей копии, а не в буфере.

- **Действия по файлу целиком — в полосе вкладок над редактором**: **Принять все**, **Отклонить все**
  (возврат файла к `HEAD` через `git checkout HEAD -- файл`, срабатывает по второму клику: откат
  рабочей копии необратим) и переключатель **Просмотрено: N**, который показывает принятые блоки
  приглушённым серым — чтобы ошибочно принятый блок можно было вернуть кнопкой «Вернуть».

- **Отметки «просмотрено» хранятся между сессиями** — в доме плагина
  (`%LOCALAPPDATA%\dsh-bsl-editor\reviewed.json`), ключ включает проект, файл и текущий `HEAD`.
  Кусок опознаётся по хешу содержимого, а не по номеру строки: сдвиг от правок выше по файлу
  отметку не сбрасывает. После коммита `HEAD` меняется — отметки прошлой ревизии не действуют,
  сравнивать там уже не с чем.

## Исправлено перед выпуском

- **Кнопки у кусков не показывались.** Сначала они рисовались content-виджетами Monaco, а у тех
  система координат — бесконечное полотно строк шириной 2^24: `right` отсчитывался от правого края
  этого полотна, и кнопки уезжали на 16,7 млн пикселей вправо, за пределы окна. Теперь это
  overlay-виджеты (слой шириной с редактор, как у навигатора «↑ N/M ↓»), вертикаль ставится вручную
  по `getTopForLineNumber`: кнопки стоят строго под блоком изменений. Проверено в настоящем браузере замерами: кнопки стоят у правого края
  левее миникарты, клик по ним доходит до обработчика, при прокрутке они едут за строкой и
  скрываются, когда блок ушёл из видимой области. Красный блок удалённых строк кнопки не закрывают.
- **Кнопки оказывались то под блоком, то над ним, а иногда их не было.** Подстраховка «снизу не
  помещается — покажу сверху» опиралась на высоту из `getLayoutInfo()`, а у редактора, созданного
  в скрытой вкладке, этот размер долго остаётся нулевым — отсюда переворот наверх. Теперь высота
  берётся у самого редактора, а кнопки ставятся строго под блоком; если низ блока вне видимой
  области, кнопок нет.
- **Плашка MCP-менеджера закрывала кнопки файла.** Она висит в том же правом верхнем углу, а свой
  сдвиг тот плагин не сохраняет — поэтому мы сдвигаем её ниже полосы вкладок правилом для
  `.dm-float` и `.dm-float-panel`.
- **Вкладки дёргались при переключении файлов.** Группа «Принять все / Отклонить все /
  Просмотрено: N» появлялась и исчезала вместе с изменениями в файле, и вкладки ездили влево-вправо.
  Теперь группа стоит последней и прижата к правому краю полосы, а вкладки идут слева — от её
  появления они не двигаются.

## Совместимость

Требуемое ядро — Harness 0.1.x или 0.2.x, изменений в контрактах нет. Новые маршруты хоста:
`POST /bsl/revert-hunk`, `POST /bsl/revert-file`, `GET|POST /bsl/reviewed`; `/bsl/git-diff` теперь
отдаёт `cachedDiff` и `workDiff` раздельно (поле `diff` сохранено, клиент старой сборки работает).

## Проверено

- `tests/_revert.mjs` — сквозная проверка на настоящем git в одноразовом репозитории: откат куска
  из рабочей копии, откат куска из индекса, откат одного куска из двух, откат файла целиком,
  отказ при чужой строке `@@` и при номере вне диапазона, запрет пути вне воркспейса, запись и
  чтение отметок, сброс отметок после коммита.
- `tests/_hunks.mjs` — разбор diff'а на куски (номера добавленных строк, блоки удалённых, якорь
  кнопок, устойчивость хеша) плюс сверка: у каждого CSS-класса, который вешает код, есть правило
  в таблице стилей.
- `tests/_http.mjs`, `tests/_chat-intercept.mjs`, `tests/_workspace-sync.mjs` — без правок.
