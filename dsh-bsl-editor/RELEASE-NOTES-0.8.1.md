# 0.8.1 — «не git-репозиторий» больше не выглядит ошибкой

Дефект из установки на чистой машине: в настройках раздела «1С-Редактор кода» висела строка
**«Последняя ошибка git — fatal: not a git repository (or any of the parent directories): .git»**, хотя
в новом проекте репозиторий инициализировался, диффы работали, а лишних процессов git не было.

## Причина

Свежий проект — это папка без репозитория, и редактор проверяет её обычным `git rev-parse`: git
отвечает `fatal: not a git repository` и выходит с кодом 128. Ответ записывался в общую переменную
«последняя ошибка git», которую и показывали настройки. Отсюда два следствия, и оба видны на экране:

- **Отсутствие репозитория считалось отказом.** Панель изменений при этом писала правильное
  «Репозитория в этой папке нет» с кнопкой инициализации — то есть одно и то же состояние
  описывалось в двух местах по-разному, и в настройках оно выглядело как поломка.
- **Ошибка была одна на весь плагин, а не на папку.** Отказ, случившийся в одном проекте, висел в
  настройках любого другого — даже там, где git работал. Обновление настроек его не снимало.

## Что сделано

- `runGit` различает ожидаемый ответ git: `not a git repository` — это состояние папки, а не ошибка,
  и в «последнюю ошибку» не попадает. Настоящие отказы (битый конфиг, лок индекса, таймаут) — попрежнему
  попадают, и по-прежнему словами самого git.
- Ошибка привязана к папке проекта: настройки показывают её, только если она случилась в этой папке.
  Успешный вызов git снимает прошлую ошибку той же папки — «последняя ошибка» не переживает починку.
- `/bsl/git-info` отдаёт поле `notRepo`: настройки говорят «В папке проекта нет git-репозитория —
  инициализация в панели изменений» вместо красной строки об ошибке. `repoError` теперь пуст, когда
  репозитория просто нет.

## Проверено

`node tests/_gitinfo.mjs` — 17 проверок, включая две новые:

- папка без репозитория: `notRepo: true`, `lastError: null`, `repoError: ""`;
- отказ в одном проекте не виден в другом: в проекте A битый `.git/config` → `/bsl/git-status`
  возвращает `bad config line 1 in file .git/config`, `/bsl/git-info` проекта A показывает эту ошибку,
  а `/bsl/git-info` проекта B в том же процессе сервера — `lastError: null`.

Остальные наборы (`_smoke`, `_gitlock`, `_stage`, `_revert`, `_hunks`, `_diffnav`, `_refresh`,
`_notice`, `_apply-order`, `_meta-changed`, `_workspace-sync`, `_layout`, `_icons`) — без изменений.
