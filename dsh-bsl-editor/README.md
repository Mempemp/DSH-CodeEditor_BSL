# dsh-bsl-editor

**Редактор кода 1С (BSL) прямо внутри DeepSeek Harness — одно окно, без code-server и Docker.**

Открой любую выгрузку конфигурации 1С во вкладке чата DSH: дерево метаданных, редактор Monaco с раскраской BSL, переход к определениям и отправка кода в чат одной кнопкой.

## Возможности

### 🌲 Дерево метаданных 1С
Левая панель переключается между обычным **деревом файлов** и настоящим **деревом метаданных 1С:Предприятия** с иконками типов — Подсистемы, Справочники, Документы, Регистры, Общие модули, … → объекты → Реквизиты / Табличные части / Формы / Команды / Макеты / Модули. Клик по модулю — и он открывается в редакторе. Поиск по имени объекта, клик по результату — и вы в нужном модуле.

Если в корне выгрузки есть папка `ExternalFiles` (внешние отчеты и обработки), в корне дерева появляется отдельный пункт **«Внешние отчеты/обработки»**: объект — это `<Имя>.xml` (описание) и папка `<Имя>/` с формами, макетами и модулем объекта. Правая кнопка по объекту — «Открыть XML» описания, левая — раскрывает его состав.

Три формата выгрузки определяются автоматически: **EDT** (`.mdo`), **XML-выгрузка из Конфигуратора** (`ConfigDumpInfo.xml`) и **пообъектная XML-выгрузка**. Дерево ленивое — парсится только то, что раскрываешь.

Режим «Изменённые» работает в обоих деревьях: остаются только файлы или объекты метаданных, в которых есть изменения рабочей копии. Файлы, которых ещё нет в git, показываются наравне с изменёнными и помечены `+`.

Кнопка **обновить** рядом с названием проекта перечитывает папку с диска: заново запрашиваются раскрытые каталоги (в режиме «Файлы») или раскрытые узлы (в режиме «Метаданные»), сбрасываются разобранные метаданные и статусы git. Нужна, когда файл или объект появился в папке проекта помимо редактора: листинги каталогов кэшируются, чтобы не дёргать диск на каждый клик, и без обновления новый файл виден только в новой сессии.

### 🎨 Раскраска BSL
Проверка Monaco на «ambiguous unicode» для кириллицы выключена (в русском коде она срабатывает на каждом файле с комментариями и строками запросов), а подсветка невидимых символов — неразрывного пробела и zero-width — оставлена включённой: в 1С они тихо ломают код.

Редактор использует **официальную TextMate-грамматику 1С** (`1c-syntax`) через monaco-textmate + onigasm. Грамматика, Monaco и воркеры отдаются плагином из `resources/vendor`; внешние CDN-источники оставлены запасным вариантом. Ключевые слова, строки, комментарии, `&Аннотации`, `#Область` — всё цветное.

### ⚡ Переход к определению по F12
Определение ищется по модели метаданных, без language server:
- `ОбщийМодуль.Метод()` / `Справочники.Товары.Метод()` → модуль и позиция;
- имя метода без точки → поиск в текущем модуле;
- повторный F12 перебирает несколько кандидатов.

F12 обрабатывает плагин; нативный Ctrl+Click Monaco не перехватывается, тост «No definition found» на промахе не показывается. Если определение не найдено или файл не BSL, в консоли остаётся строка с именем символа и путём.

«Peek Definition» из контекстного меню работает только при включённом LSP.

### 💬 Отправка кода в чат
Выдели фрагмент в редакторе → правый клик → **«Добавить к обсуждению»** → код попадает в композер DSH, готовый к вопросу модели.

### 🔵 Диффы изменений в редакторе
Изменения рабочей копии видны прямо в тексте файла: добавленные строки — с зелёным фоном, удалённые — красными блоками между строк с их текстом. Файл, которого ещё нет в git, показывается как полностью добавленный, в панели навигации — подпись «новый файл». Панель в правом верхнем углу (↑ / ↓ / счётчик) и хоткеи Alt+↑ / Alt+↓ перемещают по изменениям; счётчик считает блоки изменений и следует за позицией при скролле. Открытие файла с изменениями позиционирует на первый из них.

### ✅ Принять или отклонить изменения

У каждого блока изменений, сразу под ним справа — две кнопки. Кнопки прижаты к правому краю (левее миникарты) и едут за текстом при прокрутке. Если низ блока ушёл из видимой области, кнопок нет — они появляются, когда блок виден; над блоком они не показываются никогда.

Границы блока — по-настоящему изменённые строки: дифф берётся без строк контекста, поэтому две правки, разделённые хотя бы одной неизменённой строкой, — это два разных блока со своими кнопками, а не один общий.

- **Принять** — блок считается просмотренным: подсветка и красный блок убираются, счётчик и переход по Alt+↑ / Alt+↓ оставляют только непросмотренное. Сам файл не меняется: правка уже лежит в нём, коммит для этого не нужен.
- **Отклонить** — к состоянию `HEAD` возвращается ровно этот блок (`git apply -R` по одному изменению diff). Работает и для правок, попавших в индекс (`git add`): там откат идёт и по индексу, и по файлу. Если в редакторе есть несохранённые правки, откат не выполняется — сначала Ctrl+S.

Отметки «просмотрено» хранятся на машине и опознают правку по её содержимому: сдвиг строк от правок выше по файлу отметку не сбрасывает. После коммита отметки остаются у тех правок, что в коммит не попали, — у уехавших в коммит они уходят вместе с ними.

По файлу целиком — кнопки в полосе вкладок над редактором: **Принять все**, **Отклонить все** (возвращает файл к `HEAD`, срабатывает по второму клику) и **Просмотрено: N** — показывает просмотренные блоки приглушённым серым, чтобы ошибочно принятый блок можно было вернуть кнопкой «Вернуть». Группа прижата к правому краю полосы (вкладки идут слева), поэтому при переключении файлов вкладки стоят на месте и не дёргаются.

### 📤 В индекс и коммит

Просмотренное можно не только спрятать, но и довести до коммита, не выходя из редактора:

- **В индекс** (в полосе вкладок) — в индекс уходят только помеченные изменения, остальные строки файла не трогаются. Непросмотренная правка в индекс не попадёт: она остаётся в рабочей копии. Новый файл (его ещё нет в git) индексируется целиком — отдельных правок от git у него ещё нет. Ответ кнопки называет, что именно произошло: «В индекс отправлено 5 изменений». Изменения, которые уже лежат в индексе (их отправили раньше), называются отдельно — «9 изменений уже в индексе», и это не ошибка. Про неотправленные кнопка говорит прямо: «4 изменения отправить не удалось — файл правился после просмотра, обновите вид и отметьте их заново». Если просмотренных изменений нет вовсе, так и сказано: «Нет просмотренных изменений — отметьте их кнопкой «Принять»».
- **Всё просмотренное в индекс** (над списком «Изменённые») — то же по всем изменённым файлам проекта: идёшь по списку, отправляешь принятое, список тает.
- **Коммит** — окно со списком того, что лежит в индексе, и полем для сообщения. Коммитится индекс целиком, сообщение пишет человек.

Отправленное в индекс изменение уходит из вида файла и из счётчика: оно уже в индексе и ждёт коммита, а «Просмотрено: N» считает только то, что ещё не отправлено. Ответ кнопки всплывает полоской сверху, под полосой вкладок: появляется и затухает плавно, сам гаснет через 5 секунд и закрывается крестиком. Клики по коду сквозь неё проходят — перехватывает только сама плашка. Перед отправкой файл должен быть сохранён (`Ctrl+S`) — иначе в индекс ушла бы версия с диска, а не то, что на экране.

### 🔵 Индикаторы изменений git
Бейджи `M` / `A` / `D` и `+` (файл ещё не в git) у файлов в дереве плюс маркеры на изменённых строках прямо в редакторе — всегда видно, что поменялось в рабочей копии.

### 💬 Открытие файлов из чата
Клик по ссылке на `.bsl` / `.xml` в сообщении чата открывает файл в редакторе плагина: дерево раскрывается до файла и подсвечивает его, активной становится вкладка Editor. Ссылки на файлы других форматов и пути вне workspace обрабатываются дальше — другим плагином либо системным приложением. Отключается настройкой «Перехватывать открытие файлов из чата».

### 🔌 Опциональный LSP (выключен по умолчанию)
Поддержка `bsl-language-server` (диагностика, автодополнение, hover, форматирование) через WebSocket — **по умолчанию выключена, и плагин её никогда не скачивает**: включите явно в Settings DSH → «1С-редактор», если у вас установлен `bsl-language-server.exe`. На очень больших конфигурациях сервер может зависнуть при построении модели конфигурации.

### ⚙️ Настройки в штатных Settings DSH
Отдельный раздел **«1С-редактор»** в настройках DSH (рядом с General / Models / Side card): переключатель LSP, порт, путь к бинарнику, перехват открытия файлов из чата, состояние Git (с причиной отказа словами самого git) и путь к `git.exe`.

### 🔄 Автообновление открытых файлов
Если открытый файл изменился вне редактора (агентом или внешним редактором), вкладка обновляется при переключении на неё или возврате в окно DSH. При наличии несохранённых правок появляется плашка «Файл изменён на диске» с кнопкой «Перезагрузить с диска» — автозамены правок нет.

## Установка

Скачайте `dsh-bsl-editor-0.7.0.tgz` из последнего релиза GitHub (или соберите сами: `cd dsh-bsl-editor && npm pack`) и установите:

```sh
dsh plugin --profile web add dsh-bsl-editor-0.7.0.tgz
```

Либо по прямой ссылке на архив релиза:

```sh
dsh plugin --profile web add https://github.com/Mempemp/DSH-CodeEditor_BSL/releases/download/v0.7.0/dsh-bsl-editor-0.7.0.tgz
```

Затем перезапустите `dsh web` (host-часть) и обновите вкладку браузера (Ctrl+Shift+R).

> Если pnpm ругается на стор (`ERR_PNPM_UNEXPECTED_STORE`) — добавьте `--store-dir="<путь к вашему pnpm store>"` к команде установки.

> **Плагин не скачивает `bsl-language-server`.** LSP выключен по умолчанию и запускается только после включения в настройках — и только если бинарник найден по адресу
> `%LOCALAPPDATA%\Programs\bsl-language-server\bsl-language-server\bsl-language-server.exe`
> (или по пути, указанному вами в настройках).

## Требования

- DeepSeek Harness (`dsh web`), любая актуальная версия
- Node.js ≥ 20
- Git — для диффов, индикаторов изменений и кнопок «В индекс» / «Коммит». Ищется сам, в таком порядке: путь из настроек плагина → комплектная копия в `%USERPROFILE%\.dsh\git` → `PATH` → типовые места установки Git for Windows. Если Git не найден или папка проекта не git-репозиторий, в настройках («1С-редактор») это написано прямо, и там же можно указать путь к `git.exe`
- Windows (редактор работает везде, где работает Monaco; сам плагин платформенно-независим)

## Конфигурация

| Ключ | По умолчанию | Значение |
|---|---|---|
| `lspEnabled` | `false` | мастер-переключатель LSP (Settings → «1С-редактор») |
| `serverPort` | `8025` | порт WebSocket bsl-language-server |
| `serverBin` | `""` | явный путь к бинарнику; пусто = стандартное место установки |
| `workspaceDir` | `""` | переопределение корня workspace; пусто = workspace DSH |
| `gitPath` | `""` | явный путь к `git.exe`; пусто = автопоиск (настройки → комплектная копия → `PATH` → места установки) |
| `sourceExtensions` | `[".bsl", ".os"]` | текстовые исходники, открываемые как код |

## Поддерживаемые форматы выгрузки

| Формат | Признак | Примечания |
|---|---|---|
| **EDT** | `Configuration/Configuration.mdo` | объекты из файлов `.mdo` (реквизиты, табличные части, формы, команды, макеты) |
| **XML-выгрузка (Конфигуратор)** | `ConfigDumpInfo.xml` + `Configuration.xml` | полное дерево из плоского/иерархического списка метаданных |
| **Пообъектная XML-выгрузка** | корневой `Configuration.xml` + папки типов (`Catalogs/`, `Documents/`, …) | разделы восстанавливаются из файловой системы: Формы / Команды / Макеты / Модули / Предопределённые |
| **Внешние отчеты/обработки** | папка `ExternalFiles/` в корне выгрузки (в любом из форматов) | `<Имя>.xml` — описание (`ExternalDataProcessor` / `ExternalReport`), папка `<Имя>/` — формы, макеты, `Ext/ObjectModule.bsl`; иконка объекта — отчёт или обработка по классу описания |

Сопоставление модулей: `CommonModules/<Имя>/Ext/Module.bsl`, `Catalogs/<Имя>/Ext/ObjectModule.bsl`, `Forms/<Форма>/Ext/Form/Module.bsl`, корневой `Ext/ManagedApplicationModule.bsl` и т.д. — где бы файл ни лежал на диске, узел дерева открывает его.

## Структура репозитория

- `lib/index.js` — host-часть (ESM): маршруты `/bsl/*` (tree, read, search, git, meta, find-symbol), запуск bsl-language-server по требованию.
- `lib/metadata.js` — модель метаданных 1С: определение формата + три парсера, ленивая загрузка с кешированием, статическое разрешение символов.
- `lib/client.js` — клиентская часть: вкладка «Редактор» в conversation-view (дерево + Monaco, переключатель «Файлы | Метаданные»).
- `resources/` — иконки узлов метаданных + официальные TextMate-грамматики 1С.
- `tests/` — smoke-тесты модели метаданных и роутов `/bsl/*` (мок-ctx плюс локальный http-сервер), LSP smoke.
