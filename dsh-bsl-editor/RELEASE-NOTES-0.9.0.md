# 0.9.0 — git на большой выгрузке: таймаут настраивается

## Что видел пользователь

На машине с выгрузкой на сетевом диске панель настроек «1С-Редактор кода» показывала
**«Последняя ошибка git — git status не ответил за 60 с — папка слишком большая или её держит
другой процесс»**. При этом git находился (в комплекте бандла), репозиторий был на месте: `status`
на таком каталоге просто идёт дольше минуты, и жёсткий предел обрывал его.

## Что изменилось

- **Таймаут чтения git — 300 секунд** вместо 60. Касается `status`, `diff`, `rev-parse` и прочих
  читающих команд; запись (`add`, `commit`, `apply`) остаётся со своим пределом 15 минут.
- **Значение настраивается.** В настройках плагина рядом с «Путь к git.exe» появилось поле
  «Таймаут чтения git, с» и подсказка: на большой выгрузке и сетевом диске ставить 600–1800.
  Границы — 10 секунд … 1 час; пустое или нечисловое значение откатывается к 300.
- **git не ждёт чужую блокировку и не спрашивает пароль.** Все вызовы идут с
  `GIT_OPTIONAL_LOCKS=0` (команда чтения не берёт блокировку индекса и не стоит в очереди за чужой
  операцией) и `GIT_TERMINAL_PROMPT=0` (вместо вопроса о пароле — сразу отказ).
- **Текст отказа называет лекарство**: «…папка большая, сетевой диск или её держит другой процесс.
  Предел меняется в настройках: „Таймаут чтения git“». Подсказка про залипший `.git/index.lock`
  осталась.

## Проверено

Логика предела прогнана на извлечённых из кода функциях: значение по умолчанию 300 с, из настроек
600 с, нижняя граница 10 с, верхняя 3600 с, мусор в поле → 300 с, запись по-прежнему 900 с — шесть
случаев, все проходят. Наборов тестов у плагина нет, поэтому это единственная проверка без запуска
приложения.
